# 复盘与实际用时

关键设计问题是把“模型建议替代时段”与“用户授权更改硬性要求”分开。因此原时间、建议时间、确认状态分别保存，确认状态由输入和代码决定。另一个问题是重复请求和占用变化：使用稳定主键更新同一草稿，事务内重新验证槽位。

实际开发验证窗口：2026-11-09T12:28:24+00:00 至 2026-11-09T12:32:09.255946+00:00，约 3.8 分钟墙钟时间，不代表学生本人投入；后续整理和交付时间另计。建议三小时预算未用满。

未完成：真实模型验证、至少两条 live 动态路径、GitHub 发布和最终 SHA、评审账号权限、本人修改和反思。下一步优先实际模型运行，再依据失败 Trace 改进提示和错误恢复，不优先做界面。

## 接入失败后的改进
首次版本错误假定用户使用 OpenRouter，且只记录异常类，导致用户多次替换 Key 仍无法定位。实际问题是平台与凭证不匹配。改为明确的智谱普通 API 配置，并保留脱敏 HTTP 状态码/平台错误码。这个改动使故障能在模型接入层被解释，而非误归因于业务逻辑。

本轮增加真实运行一键验收脚本，把用户操作缩减为本地输入密钥和执行一个命令。此轮耗时另计，不能沿用首版几分钟的开发窗口作为整个项目投入；累计实际时间尚待结合用户终端操作补充。
