# 用户、目标、范围和成功标准
用户为内容团队。输入素材 ID、元数据、硬性发布时间、已有时段和审核规则；输出审核状态、风险原因、建议时段、待确认项、草稿保存结果。

| 编号 | 验收点 | 可检查标准 |
|---|---|---|
| A1 | 正常排期 | 无风险且时段空闲，保存草稿；published=false |
| A2 | 素材信息缺失 | 列出缺失字段，不保存 |
| A3 | 规则风险 | 标明风险原因并阻断保存 |
| A4 | 时段冲突 | 提供可用替代时段，保留原始要求并标记待确认 |
| A5 | 重复提交 | 同一素材、原要求、campaign 只保留一份草稿 |
| A6 | 保存失败 | 明确 failed，数据库没有新增草稿 |

所有输入时间视为硬性要求；替代时段仅是提案。只有用户输入 confirmed_slot 才确认该精确替代时间。仅草稿，不真实发布。

合成资料 M01 正常、M02 缺少 rights、M03 命中“保证收益”。规则为教学用必填字段及关键词规则，不代表完整内容合规审核。默认共享单一发布资源、固定时间槽，不处理时长重叠或多渠道容量。草稿提案也占用槽位，这是保守的防冲突设计假设。真实业务规则可替换 data/fixture.json。
